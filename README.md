# 彩条提取工作台

本地 Windows FS 矢量提取工具，直接导出源文件曲线，不依赖 Flexi 界面操作。
当前版本为独立曲线识别版：新提取任务不读取、查找或匹配任何参考库。

## 运行与使用

打开 `release/独立曲线识别版_20261019/彩条提取工作台/彩条提取工作台.exe`，
或双击桌面“彩条开发工作台（最新版）”快捷方式（调用根目录 `launch_latest.ps1`）。启动时对比当前本地源码与发布包的指纹；一致则直接打开，没有对应版本则自动调用打包程序，自检成功后打开新版。打包期间显示等待提示；失败会显示错误和日志路径，旧包保留。保留程序旁的 `_internal` 文件夹。
源码方式：安装 `requirements.txt` 后执行 `python app.py`。

桌面快捷方式需要自动打包时，会先将当前仓库中未被 `.gitignore` 排除的改动（含新增、修改和删除）提交为一次本地 Git 备份，再开始打包；不推送远端。没有新改动时沿用已有提交，不生成空提交。已有对应发布版而直接启动时不提交。备份失败或存在合并冲突时停止打包并提示日志；发布包的 `build-info.json` 记录备份提交号。手动打包可加 `--backup-git` 使用同一行为。

1. 添加 FS 文件或文件夹，设置输出目录与并发任务数。
2. 在 AI 配置中设置兼容 Chat Completions 的图片模型、接口地址及本机密钥。
3. 勾选六类提取后，识别车身、车漆、彩条、文字、logo、门徽；取消勾选则仅提取彩条。
4. 对照原稿检查结果，可按对象 ID 补选、排除，也可进入六类复核画廊确认图案。识别有误或候选缺失时，选好类别，点击“识别不正确？在原稿上点选 / 框选本类对象…”，手动指定车身、车漆、彩条、文字、logo 或徽章。
5. 在六类复核页为每个候选选择“来源视图”，点击“添加此图 / 更新此图来源视图”。每类可连续添加多个方向，也可添加同方向的多个图案。选中已添加项可预览、修改方向或移除；没有图案的类别仍须确认“该类没有图案”。
6. 导出 SVG 与透明 PNG，在车名根目录下按类别多层子目录结构存放：整车底图存放在 `整车底图/`（包含 `vehicle-base.svg/png` 及槽位配置），各图案按类别存放在 `车身/`、`车漆/`、`彩条/`、`文字/`、`logo/`、`门徽/` 子目录下，每个图案独立保存为 `{来源视图}_{类别}_{序号}_{FS文件名}.svg / .png`，例如 `彩条/左视图_彩条_01_示例.svg`。`复核记录.json` 位于车名根目录，方向同时写入 SVG 元数据和 `复核记录.json`，下次打开可恢复。AI 分类时同时识别候选的来源方向，复核页自动预填，同一源视图内的零部件可沿用整车方向，人工可更正。可选左、右、前、后、顶、底、整体视图、独立图案和混合视图；左右以车辆自身为准。位置本身不能决定方向；无法判断或来源冲突时保留“待确认视图”。旧任务需重新 AI 提取或在复核页手动指定方向。重跑和人工修正创建独立版本，保留旧版本。

六类候选包括原生组合、独立源曲线（SourcePath）与空间组合（SpatialPaths）。
空间组合只是供视觉模型判断的提议，不能凭同色或相邻直接认定为彩条。
单条候选仍可选，可组合多色设计或排除结构曲线；规则不绑定文件名、固定颜色或对象编号。
AI 只选择已提供的源对象 ID，不重画曲线。未知、缺失或不确定类别保持为空并要求复核。

复核导出窗口的候选大图左上角显示“原稿位置”缩略图，红框标出当前查看图案在第 1 页中的范围。切换候选、翻页、切换类别或查看已添加图案时自动更新；原稿无法读取时明确标注为提取对象预览。定位预览在后台生成，不修改来源视图标记与导出选择。

AI 六类提取同时识别原稿区域，以已有完整车辆视图或独立素材候选为锚点计算源坐标边界。候选及手工补选的对象按区域自动拆分，车身、车漆、彩条、文字、logo、徽章继承同一区域名称，无需逐张选择方向。打开“查看原稿区域 / 统一修改区域名称”可核对区域框并统一改名；左右不确定时先用“侧面区域A/B”。成品文件名为 `子目录/区域名称_类别_序号_FS文件名.svg/.png`，单类 SVG 图层同样带区域名称，复核记录保存区域归属和改名。没有完整锚点、多个区域重叠或跨边界的对象保留待确认；旧任务没有区域时可手工标注，启用 AI 重新提取后才有新的区域识别。区域归属只组织现有源对象，不切割或重画曲线，六类仍须人工确认后导出。

车漆确认后，成品另附 `整车底图/vehicle-base.svg`，其中 `layer-paint`（车漆）与 `layer-body`（车身）是可直接读取的 SVG 图层；原始填充、渐变、轮廓线和源对象 ID 保留。各类单独 SVG 同样包含对应图层。车漆候选新增大面积填充通道，允许直线闭合面和渐变，不按固定颜色定类。本工具负责提取和标注；AI 推荐颜色及换色由外部网页实现。详见 [SVG 图层与网页交接约定](docs/vehicle-paint-recoloring.md)。

手动选择界面显示当前任务可导出的原稿对象，不受 AI 候选组合限制。点选按最小对象边界命中；拖框只选完整包含的对象。可切换添加、移除、平移，滚轮缩放，支持撤销、清空和所选内容预览。重叠对象可用右侧列表定位并增减。点击“确认所选对象为…”才添加至本类；取消保留原选择。修正后的对象组合会作为一个新图案加入，原有错误图案可在已添加列表中移除。完成六类确认后再导出，复核记录会保存手动指定的源对象 ID，下次打开可继续修改。当前对象池沿用现有提取页；未被 FS 解析器提取的对象无法在此补画或选择。

接口地址、模型和 API 密钥可直接在界面查看、修改，明文保存在本机 `settings.json`，支持 HTTP / HTTPS，无需配置环境变量。旧版环境变量和 `.api-key.dpapi` 仍可读取，首次通过新界面保存后使用 JSON 中的密钥。配置和密钥不提交 Git。
当前提取逻辑以 `1c6162f` 为基线，加回 CMYK 红/橙色、无填色透明、LAB 颜色读取修复，以及社内/Gemini 快捷切换与双窗口对比。基线自带的车身残留面补查随版本恢复；之前的六类门禁等改动未加回。

六类 AI 支持按模型调整请求：默认 Qwen 从首轮按区域、每批最多 12 个候选识别，同一区域的结构组合与独立漆面配套送审，保留原 G 编号；另附原稿局部与红框编号定位图。区域仅为几何上下文，不会自动定类。其他模型首轮保留整张图集方式；六类全空时，再按区域、每批最多 20 个放大复核。随后以明确选中的车身为区域，合并已选车漆与残留小面复核，提供原稿、定位、当前车漆三列对照，可补选漏面、撤回误选或改判装饰。共享源曲线的冲突集中复核，仍冲突的组合留给人工归类。补查不再截断到 120 个，所有符合条件的残留面均分批送审，已选车漆重审不挤占补漏名额。Qwen 漏答编号时继续拆半补问，最小至单对象仍失败才停止，不把漏答当作不提取。分批可能增加调用量，模型判断仍须人工确认。更新后须重启新版应用并重新提取；旧结果不会自动改变。详见 [区域车漆复核](docs/ai-request-diagnostics.md#区域配套送审与车漆完整性复核)。

主界面的“AI 调优…”可设置批量、提示方式、输出上限和采样参数；“AI 请求明细…”显示每批候选数、实际 HTTP 尝试、耗时、图片尺寸、发送参数和接口返回的 token 用量。请求记录不包含密钥、接口地址或图片原始数据。详见 [AI 请求诊断与 Qwen 调优](docs/ai-request-diagnostics.md)。

多稿件对照脚本可比较原 Qwen、结构化局部复核 Qwen 与 Gemini，保留请求计数、断点缓存和同坐标预览；默认不调用接口。运行方法及结果解释见 [多稿件 AI 提取对照](docs/ai-extraction-benchmark.md)。

双击 `scripts/双开AI对比.cmd` 可打开社内和 Gemini 两个独立窗口，配置和输出目录相互隔离。单窗口切换用 `scripts/切换到社内AI.cmd` 或 `scripts/切换到Gemini.cmd`。配置说明见 [AI 配置快捷切换](docs/ai-profile-switching.md)。

“测试连接”只验证文字请求，不代表真实图片请求一定可用。可以在配置窗口调整是否使用系统代理。
图片请求采用流式响应，完整收到正常结束标识后才校验 JSON，断流、截断及未知 ID 均拒绝。
临时网络或可重试 HTTP 错误在总超时内最多尝试三次；不会自动换模型或降级识别。
实际任务并发不超过本批文件数，每个任务使用独立工作进程。

## 限制

- 当前仅处理第 1 页，复杂布尔操作、裁剪、部分字体、纹理及其他原语尚未全面支持。
- 候选有数量和几何筛选限制，拆散、细小或未解码的对象可能遗漏。
- 模型置信度未经准确率校准，仍需检查多选与漏选。
- SVG 使用源曲线坐标，但物理比例未验证，不能直接据此确定下料尺寸。
- 复核导出界面有一项 Tk 线程清理测试异常，详见独立识别验收说明。

## 开发与文件管理

每次通过桌面快捷方式自动打包或运行 `scripts/build_windows.cmd`，都会同时在 `release/` 生成 `彩条提取工作台_源码体验版_时间_编号.zip`，适合发给同事体验；本机仍启动 EXE。体验 ZIP 只含运行源码、空配置模板、依赖清单、安装/启动脚本、说明和文件校验清单，不含 EXE、本机配置、密钥或素材。也可使用 `python -X utf8 scripts/package_source.py` 单独生成。

打包前会用真实 Python 3.10 编译检查源码包全部 Python 文件，再运行源码和 EXE 启动自检；检查失败就停止发布。维护者需安装 CPython 3.10（可用 `uv python install 3.10`，不切换默认 Python）；兼容检查不会联网下载解释器。同事运行 EXE 无需安装 Python；使用源码体验包时仍按下方说明安装环境。

体验包启动脚本自动选择已有的标准 CPython 3.10～3.14 x86-64，优先使用已装齐依赖的版本。解压后首次运行“01_首次安装环境.cmd”，依赖安装到所选 Python 当前用户的共享环境；已有依赖版本符合要求时跳过下载和安装。后续解压新版本可直接运行“02_启动程序.cmd”，依赖缺失或版本变化时才需重新执行安装脚本。此方式不再为每份解压目录创建 `.venv`，不更改系统默认 Python。

以后打包直接双击 [`scripts/build_windows.cmd`](scripts/build_windows.cmd)。脚本使用仓库 `.venv`（如存在）或 PATH 中的 Python，检查依赖、运行源码自检、生成 EXE、运行打包版自检，再生成并检查 ZIP。所有步骤成功后，才把带时间和唯一后缀的新版本保存到 `release/`；旧版本保留，“启动最新版”入口会找到新包。双击窗口会保留成功结果或错误信息。

也可从任意目录运行 `python -X utf8 "仓库路径/scripts/build_windows.py"`，或加 `--label "我的版本"` 自定义发布目录前缀。依赖不齐时脚本会给出安装命令。本机新版 EXE 会自动沿用仓库及已有发布目录中最近保存的 `settings.json`，并同步复制该配置同目录的加密密钥；通过桌面“最新版”快捷方式打开即可沿用 AI 配置。加密密钥绑定当前 Windows 用户。供分享的 ZIP 只附配置模板，不含本机配置和密钥；他人解压后需自行配置。自检不调用收费接口；自检不替代真实 FS 的识别验收，也不自动运行完整单元测试。

构建文件位于 `build/`；日志位于 `.local/tasks/YYYYMMDD_packaging/`。失败时保留构建现场并返回非零退出码，不覆盖已有发布包。

AI 修改先阅读 [AGENTS.md](AGENTS.md)，遵守 [仓库文件管理规范](docs/repository-management.md)。
源码和有效测试保留现有位置；新增文档、脚本、测试分别进入 `docs/`、`scripts/`、`tests/`。
临时结果放 `.local/tasks/`，应用结果放 `output/`，构建中间文件放 `build/`，发布包放 `release/`。
清理记录见 [2026-10-19 清理记录](docs/maintenance/2026-10-19-cleanup.md)。
