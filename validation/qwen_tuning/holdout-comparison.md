# 多稿件 Qwen 工程复核对照

日期：2026-10-21—22。基于 `fd6a54f` 的未提交工作区。使用真实本机配置接口；没有修改应用默认配置、服务端上下文窗口或业务提取逻辑，没有打包、提交 Git 或替换发布包。

## 方法与核查边界

将沙漠开发稿上有效的结构化局部复核协议固定后，另选三份复杂稿件：渐变、细线多色加复杂标识、大面积多色。它们不是随机抽样，不能据此推断所有稿件的准确率。首轮均从同源 120 个候选开始；后续候选池由各流程自身的决策生成。这是完整工作流比较，没有逐因素消融。

- 原 Qwen 使用应用流程，每批 12 个、简洁提示、temperature=0、top_p=1、输出上限 8192。
- 工程 Qwen 复用自己的首轮车身锚点，再按车身关联、补查混合组和车漆、保护文字及标识、逐路径复核。推理不读取 Gemini 答案或离线参考。
- Gemini 使用现有整图集、详细提示的应用流程。它是对照，不是真值。
- 两种服务分别顺序处理稿件，服务之间并行。耗时为请求记录累计值，不是稳定吞吐或计费评测。工程 Qwen 的成本包括依赖的首轮；全实验实际请求数另按唯一请求 ID 统计，避免重复计算复用首轮。

离线参考来自助手查看原稿、原生组合和源路径的核查，未经用户确认，不是独立人工标注或正式准确率。图案单元按渐变图案、波纹和棕榈等可独立构成的完整图案计数，不等于车辆视图套数；海南稿重叠的棕榈源副本作为等价选择。遗漏、混入及完整单元均按该参考核查，并保留同坐标渲染供复审。

推理提示和候选算法在三稿测试期间保持固定。期间完善了断点命令、缓存安全测试、失败诊断及离线汇总；计划记录初始脚本哈希，后续脚本字节变化不代表推理协议升级。冻结提示摘要和输入哈希保存在脱敏指标中。

## 结果

**这版没有在三份新稿件上表现出稳定提升，不应直接设为默认，更没有足够证据声称超过 Gemini。** 渐变稿三者相同；海南稿工程版退步；大面积稿工程版虽移除了原有黑色结构，却新增两个参考外棕色端块，仍漏正前方色带，整体优势尚不能确认。

全实验按唯一请求 ID 去重，共 **137 次逻辑请求、139 次 HTTP 尝试**；一次请求因断网失败，含两次重试。请求耗时合计 3477.696 秒，服务之间并行，不能当作墙钟运行时长。工程版表格重复计入其依赖的首轮是为了呈现独立方案成本，未将这些复用请求重复计入全实验实际调用量。三份原稿 SHA256 在运行后均与冻结计划相同。每种方法仅跑一遍，没有验证随机波动或统计稳定性。

## 已确认的工程问题

海南稿中，原 Qwen 混入调色板色块；工程版仍保留一个色块，并混入四条文字碎片，同时丢失更多有效波纹层。对照源路径和候选成员，工程版未选的可接受路径既不在首轮 120 候选的成员内，也未进入末轮局部复核，未被文字保护规则排除；按等价副本核查，最少缺 13 条。这说明补漏入口和候选覆盖先于末轮模型判断出现问题；不能仅靠增加末轮请求或上下文窗口解决。

工程版记录整车级混合组超限待复核，不能将被跳过的组当作已识别完成。现有残留补查要求原生上下文有已选彩条种子且能唯一归属车身；逐路径提案又有车身内归属和相对面积门槛。代码中的这些入口会限制独立图案和细线层的覆盖，未单独消融其各自影响。下一步应优先保留完整装饰父组、覆盖车身之外的独立图案、核查被其他标签提前排除的装饰，并对调色板及文字碎片设置有上下文的复核。上述方向尚未在本轮实现或验证，不能宣称已修复。

第三稿 Gemini 初始彩条提案包含两侧和后部共 23 条路径，但车漆父组与彩条共享源路径，应用跨类校验拒绝，不能当作成功导出，也不能表述为模型完全没识别彩条。
