# 六类候选检验门禁

AI 六类提取自动执行：首轮分类 → 车身残留面补查 → 六类门禁 → 生成候选。手工模式不调用模型。门禁检查的是解码后的源对象选择，不重画原始曲线，也不代替人工确认。

## 检验与修复

- 候选生成器保留首轮数量上限之外的组合，门禁按原稿区域分批检查，每批默认 12 项。车身里残留的较大有色填色面优先送检，避免长条空调罩等单路径漆面排在原生图形组合之后而耗尽预算；排序不直接决定类别。没有明确区域的对象进入未归属范围，按当前页范围提供局部图；不凭位置猜测左右。
- 每次提供原稿局部、带 ID 的候选、六类选择预览和未选对象。六类预览使用与组件导出相同的 `layered_svg` 和归属规则，保留原稿位置、源曲线、填充、渐变及绘制顺序。
- 额外读取 FS 的独立内嵌预览，与整页解析图对照；它可能过时或分辨率不足。模型的 `consistent` 仅代表本次视觉对照一致，不证明解析器完整支持 FS。
- 模型按车身、车漆、彩条、文字、logo、门徽逐类输出具体疑点和已有候选 ID 的增删。类别移动同时删除旧类别并加入新类别；仅门徽与 logo 允许共享图形。完整门徽修复保留补入的号码，不再被旧弧形文字提案收窄。
- 所有增删必须限定在本页候选与本区域源对象内，且通过全局对象归属校验。复合增删先一起验证，不会提交半套跨类移动。
- 车身残留基础漆面是必查项，覆盖车顶、空调罩、导流罩、镜壳和前后端面。AI 明确提出同一候选从车身转入车漆时，系统把原始填色成员作为迁移提案，黑灰无填色描边保留在车身；有未支持填色的组合不作部分迁移。玻璃、灯具、彩条不能仅凭颜色归入车漆。
- 这类迁移先单独渲染并复验，核对车身已剔除、车漆已补齐、源形状/颜色/渐变/位置及结构轮廓正确。复验通过才保留；失败、不确定、原稿不一致或预算不足均不提交。已经通过的迁移独立保留，后续文字、门徽或其他页失败不会把它撤销。其余修复仍按区域整轮验收。
- 除已单独复验通过的车身转车漆迁移外，每轮对各页依次应用暂存修复；修复之后须重新检查整个区域。只有所有页在一轮内均通过且没有新修改，才提交该区域暂存修复。接口/协议/渲染失败、无效增删、循环、修复轮数上限、时间/请求预算耗尽均回退该区域暂存修复。其他已通过区域和独立复验的漆面迁移保留。

## 配置

在本机 `settings.json` 配置，界面保存其他 AI 设置时保留这些字段；也支持 `LIVERY_` 加字段大写的环境变量。

| 字段 | 默认值 | 范围/含义 |
| --- | --- | --- |
| `audit_enabled` | `true` | 启用六类门禁；关闭时报告未执行 |
| `audit_page_size` | `12` | 每页 4～24 项候选 |
| `audit_max_requests` | `16` | 每份 FS 最多 1～64 次门禁请求（不含首轮和旧残留面补查） |
| `audit_repair_rounds` | `2` | 最多 0～3 轮修复；0 表示只检查 |
| `audit_timeout_seconds` | `240` | 门禁总时间预算 1～600 秒；每次接口超时取剩余预算与原接口超时的较小值 |

门禁使用同一个已配置的视觉接口，不自动更换模型。会增加耗时与接口用量；增大预算只增加检查范围，不等于提高准确率。工作进程的整份文件超时仍适用。

## 报告与界面

运行目录的 `candidate_audit/` 保存初始分类、各区域各轮检查图、检查响应和汇总 `report.json`。车身转车漆的复验保存在对应页的 `body_paint_recheck/`，汇总的 `body_paint_transfers` 记录已保留的源成员；这些请求共用门禁时间与请求预算。这些是运行产物，不纳入 Git。最终组件报告与任务 manifest 中的 `quality_gate` 保存汇总，运行日志和复核画廊显示状态与保留的修复数。

- `semantic_status=passed`：所有排队检查页完成视觉验收。
- `status=passed`：语义检查完成，独立预览视觉对照一致，且没有已发现的未支持源对象。
- `status=review`：存在疑点、未检查页、源对照缺失/不确定、失败或预算限制。具体记录在 `unresolved`。
- `status=not_run`：手工模式或配置关闭。
- `status=stale`：人工修改了类别选择，原门禁结论只适用于修改前版本，不会自动发起付费复验。

这些状态均不将 `human_reviewed` 改为真，也不自动越过原有导出确认。没有进入解析结果的源对象无法靠增删修复；低清预览、小图标、复杂遮挡、布尔/裁剪效果仍可能漏检。候选按原生组合、已有子组与未被原生组合覆盖的散路径分批检查，不将数万条结构轮廓全部展开成单图；检查通过不等于逐条证明所有底层路径的语义。没有可操作的细分候选时保持待复核。

## 验证

离线回归：`python -X utf8 -m unittest tests.test_candidate_audit -v`。测试模拟模型响应，覆盖玻璃误入彩条、漏掉宽曲线、门徽电话号码、跨类移动、共享标志、复验提交、失败/预算/循环回退、候选覆盖、独立预览及请求证据。普通测试不访问真实接口。

未知 FS 的无需人工修改比例，需要用人工确认的正确样本及独立新文件评估。当前实现没有训练模型，也没有启用历史人工结果的自动复用；现有独立识别不使用参考库的约定保持有效。
